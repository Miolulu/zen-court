# 小沙弥静修 · 3D 真实在线原型

一座可以**走进去**的禅意寺院（第三人称 3D，真实多人在线）。**纯场景交互**：没有动作按钮、没有操作说明、没有进度条和目标，悬停高亮 + 标签告诉你什么能碰，走过去才能碰。无人时庙里便空着。

> **场景布局参照 `sansatemple.com`（山寺 / 清缘堂）**：林中敞口木构大殿、正中一尊大佛 + 佛后壁画、佛前供桌、**中轴一座香炉**、佛前**每排 10 张、成排铺开的拜垫并留中轴过道**。本作只复刻空间构图、镜头语言与交互机制，**未使用对方的模型 / 贴图 / 音频 / 代码**。
>
> 已完成一版**治愈系中国风绘本**美术：远山雾景与大佛为 AI 生成原画，建筑 / 人物 / 器物是自建几何体配程序化贴图与绘本色阶，UI 走宣纸朱印风。所有素材均为本项目自制或生成，无第三方版权素材。

原站单房 100 席 / 100 人（`fr(i)`：每排 10 垫、10 排、`x=±2.4…`、`z=-8.4+排×2.8`）。本项目**在线上限 50 人**，因此按同样比例做 **10 列 × 5 排 = 50 张拜垫**，一垫一人，正好对应容量。

## 运行方式

Windows 双击 **`start.bat`**（自动检查 Node、首次装依赖、起服务、开网页）。或手动：

```bash
cd zen-court
npm install
node server.js
```

浏览器打开 **http://localhost:8787**。必须经 http 访问（ES module + importmap，`file://` 会被拦截，此时页面显示引导提示）。WebSocket 地址与页面同源动态生成（https→wss），日后部署到局域网 / 公网不必改配置；目前仅在本机运行。

## 场景与交互

- **大殿**：月台台基、石阶只铺中轴（月台压边防穿模）、红柱（中轴不立柱）、金色格扇（中轴留空）、**檐下椽子 + 柱头斗拱 + 50 道瓦垄 + 一排金色瓦当**、歇山飞檐、木底金边「静照院」匾额、10 盏六角宫灯；四周松林与三株银杏、两座石灯笼（移至 `±9.6, z=-2.6`）、东南角荷池。庭院物件全部移出拜垫阵列，角色行走由 `clampWalk()` 约束（不出院、不上殿基、不下池）。
- **一尊大佛**：水彩原画立绘（含舟形背光与莲台）嵌在深色 3D 佛龛里，背后是柔光壁画与呼吸的佛光；3D 莲瓣、须弥台、供桌烛台供果。点大佛 → 走到佛前最近的拜垫跪下（已跪则起身）。
- **佛前香炉**：**只有一座**，LatheGeometry 车削的三足双耳铜鼎（鼓腹 + 弦纹 + 炉内香灰与残香），立在大佛与第一排拜垫之间的中轴过道上。走近后弹三步上香界面；**三炷插满后香筒灰化封顶**，提示「三炷已满 · 心诚则灵」，不可再取。
- **50 张拜垫**：约 0.28 高的矮蒲团（布料贴图），5 排 × 每排 10 个，中轴留过道；hover 显示「第 N 排 · M 号拜垫」。点垫子 → 走过去 → **踩上垫面、双膝落垫、上身前俯合十、锁定面朝大佛**并保持，再点一次才起身。角色不再沉入地面或插进蒲团；当前垫子与脚下会泛暖光。跪 / 起同步给同庙的人。
- **寺猫不是摆件**：造型整体重做（胸/臀双球 + 虎斑扁椭球 + 竖瞳 + 白口鼻 + 曲线尾），有地盘和作息，会巡院、端坐、舔爪洗脸、伸懒腰、蜷着打盹、蹲蒲团、去池边看鱼、扑飘动的光点、蹭走近的人、被木鱼声惊到；被点名时坐下来等人走过来，撸完自行散去。眨眼、耳朵、尾巴、呼吸、跳跃都有独立动画。
- **东南荷池 · 三足金蟾**：池心石上蹲一只口衔方孔铜钱的**三足金蟾**（断一足惩戒、吐宝招财的民俗设定）。点金蟾走近后弹抛币界面：**点水面抛硬币，投进蟾口 → 金光吐宝、功德 +8；落水 → 涟漪水花、功德 +1**。每日 3 枚（localStorage 按日期计数，跨天自动重置），投完显示「今日三枚已投 · 明日再来」，再点无效。
- **跪拜起身朝向**：跪下锁定面朝大佛；**起身时面向鼠标所指方向**（指脚下则面向镜头），转身用最短弧限速平滑过渡，侧身过程可见，不再瞬间背身。
- **其他活物**：烛火摇曳（猫跑动带起气流会多偏一点）、香烟袅袅、池水一圈圈涟漪 + 小鱼偶尔跃出、逗猫光点自己飘、小沙弥与同修待机呼吸 / 眨眼 / 轻转头。
- **悬停 / 走近**：可交互物泛金光 + 地面呼吸光环 + 鼠标旁标签；距离不够显示「走过去」，点击后小沙弥**走到跟前才触发**，绝不隔空生效。点空地只走过去。细碎装饰一律关闭 raycast，改挂不可见点击盒（念珠细环同样有放大命中区）。

### 独立放大界面（走近后弹出，Esc / × 收起）

| 物事 | 界面内容 |
|---|---|
| 木鱼 | 放大木鱼 + **从画面右下角之外斜伸进来的木鱼棒**（第一人称手持感，**不画手**）；点击绕握持点挥下砸中木鱼，棒头泛光、火花、涟漪、「第 N 敲」 |
| 念珠 | **放大的竖椭圆珠串（76vmin / 580px）**、14 颗 + 虚线穿绳，**没有手**；上下拖拽 / 滚轮 / 点上下半区 / `↑↓` 竖拨，当前珠发光、「第 N 念」 |
| 上香 | 「取香 → 就烛点燃 → 插入香炉」三步，香支真正立在炉中（红头 + 青烟），最多留 3 炷（**满三炷香筒灰化、不可再取**），「第 N 炷香 · 青烟袅袅」 |
| 抛硬币 | 池畔三足金蟾俯视一池水：点水面抛硬币，**投中蟾口金光吐宝 +8 功德，落水涟漪 +1**；每日 3 枚，用完温和收口 |
| 撸猫 | 放大版猫，**按住拖动顺毛**才有效：眯眼 / 摆尾 / 爱心 / 呼噜 / 好感增长 |
| 点灯 | 一盏**灭着的长明灯**：先输入愿望（≤24 字），再**点灯芯**点亮；火焰亮起、灯旁愿签显示「法号 的愿 + 愿望」，底部「今日已点一盏」 |

**点灯规则**：服务端按「法号 + 服务端日期」权威校验，**每人每日最多 1 盏**，跨天自动清灯；今日愿灯下发给全庙，在 3D 檐下灯笼上挂愿签，hover 可以看到完整愿望。断线时前端 localStorage 兜底，不会误以为能点第二盏。

**音效**：木鱼 / 念珠 / 点灯改为**离线物理建模生成的 WAV 采样**（模态合成中空木腔 + 木槌瞬态，见 `tools/gen_sfx.py`），比原先的振荡器写实；由 `Sound.loadSamples()` 预载、首次手势后播放，`sfx/` 目录留作日后替换真实录音。诵经氛围音、猫呼噜、磬声仍是 Web Audio 实时合成（非真人诵经）。

## 美术（治愈系中国风绘本）

**统一风格锚点**：柔和水彩 + 不透明水粉、暖琥珀夕照、雾青灰 / 赭石 / 米白 / 苔绿的低饱和配色、宣纸颗粒、柔和手绘线条、低对比、大量留白。所有生成提示词逐字复用同一段风格文字，避免素材拼贴感。

| 层 | 做法 |
|---|---|
| 原画 | `backdrop.jpg` 远山雾景（已去水印、底部淡出雾白）垫在寺院后方；`buddha.webp` 透明底水彩大佛立绘嵌进 3D 佛龛，深色衬底防止浅色原画被洗白 |
| 贴图 | `stone / wood / tile / fabric / paper / leaf / glow / mural` 由 Python 离线生成的可平铺纹理；每个用途独立 `TextureLoader`，规避 `clone()` 在异步加载完成前拿到空 image 的坑 |
| 光照 | sRGB 输出 + `ACESFilmicToneMapping` + `PCFSoftShadowMap`；暖金斜阳（投影）+ 冷色补光 + 佛前点光 + 半球天光 + 暖雾 |
| 建模 | **核心三件（小沙弥 / 拜垫 / 金蟾）由 Blender 4.2 建模导出 GLB**；大佛采用 AI 水彩原画平面立绘（ 已按边缘洪泛去除白底、带透明通道与羽化边，嵌在深色佛龛 + 呼吸柔光中）。流程：AI 生成参考图 + 用户提供的 5 张理想图（持珠小和尚 / 圆胖大眼蟾 / 布偶猫）→ 拆件表 → `tools/gen_blender_models.py` 重建。小沙弥：大头比例 + A 形袍波浪下摆 + 垂坠喇叭袖白衬边 + V 交领 + **双手捧念珠环（跪拜时展示）**；金蟾：**圆胖团子放样身 + 大白肚 + 头顶大眼环形眼睑 + 前臂合抱 + 口衔小钱**（两前两后腿，按参考图）；猫：程序化改布偶色点配色（奶油身 + 深棕耳尾）。运行时 `GLTFLoader` 按材质名覆盖为游戏 toon/贴图材质、按节点名接管动画，缺件回退程序化。程序化精修：宫灯灯骨金箍、石灯笼春日形制、双层莲瓣、供桌贡品 |
| 动效 | 银杏落叶精灵、萤火光斑、烛火摇曳、香烟、池水涟漪、佛光呼吸、跪拜暖光、走路起伏、hover 柔光盘、界面转场 |
| UI | 宣纸底纹 + 朱印法号牌 + **卷轴式进场赐名** + **自己头顶朱红法号牌**；五个放大界面统一纸纹金边与转场；满员提示同风格 |

AI 生成原图保留在 `assets/art/backdrop.png` / `buddha.png`，运行时用后处理过的 `.jpg` / `.webp`。重跑 `python tools/gen_art.py` 可重新生成全部程序化贴图与去水印版本（依赖 Pillow，numpy 可选）。

## HUD（只有三个数 + 法号）

| 显示 | 含义 |
|---|---|
| 法号 | 进庙时服务端随机赐予的两字法号，sessionStorage 沿用、庙内去重。**进场先弹宣纸卷轴大字展示法号**（约 6.5 秒或点击收起），之后常驻左上朱印法号牌，并在**自己头顶挂朱红法号牌** |
| 修行时长 | 本次进入页面后的时长，不持久化 |
| 功德 | 累计功德数，localStorage 持久化 |
| 今日修行 | 今日累计修行时间，按本地日期持久化、跨天归零 |

无目标、无进度条、不限制在线时长。左下角一行极淡的在场状态（含「全庙 50 席」），右上角声音 / 重置两个小钮（非动作按钮）。**右下角固定工具坞**：木鱼 / 念珠两枚常驻按钮（宣纸浅底），点开即进放大界面，不必再去场景边角找。键盘：`Esc` 收起界面、聚焦界面内 `↑/↓` 拨念珠、`空格/Enter` 敲击、`M` 静音。测试辅助：URL 加 `?wipe=1` 可跳过确认直接清空本地存档。

## 多人（真实同庙在场，上限 50 人）

`server.js` 同时托管静态页面与 WebSocket，追踪每个玩家的 **x,z 位置 + 动作 + 法号**，广播入庙 / 走动 / 动作 / 离庙 / 在场人数 / 愿灯。`MAX_PLAYERS = 50`，**满员时第 51 位收到 `full` 并以 1008 关闭**：不赐法号、不进快照、不广播入庙；前端显示温和的「庙中已满」提示并 20 秒后静默重试，有人离庙即可补位。

协议：

- 客户端→服务端：`{type:'hello',name?}`（沿用旧法号） | `{type:'move',x,z}` | `{type:'action',pose}` | `{type:'lightLamp',wish}`
- 服务端→客户端：`welcome{id,x,z,name,capacity,peers[],lamps[]}`、`peerJoin`、`peerMove`、`peerAction`、`peerLeave`、`presence{count,total,capacity}`、`lampOk{lamp}` / `lampDeny{reason,lamp?}` / `lampLit{lamp}`、`full{limit}`
- 法号由 `NAME_A × NAME_B` 随机生成两字、`usedNames` 保证庙内不重名；快照 `peers[].pose` 让后进来的人立刻看到谁正跪着。
- 入庙出生点在殿前中轴（沿石阶走进大殿），镜头横向跟随，保证自己的小沙弥始终在画面里。

单人无 NPC、无假人数；连不上服务时只显示「未连接 · 庙中空着」。

## 文件结构

- `index.html` — 全屏页面骨架（importmap + 宣纸 HUD + 进场卷轴 + 悬停标签 + 5 类放大界面 + 满员提示 + 启动兜底）
- `game.js` — 全部 3D 逻辑（场景 / 生态 / 悬停 / 走近判定 / 跪拜 / 放大界面 / 音效 / 多人 / 计时）
- `server.js` — 真实多人后端（50 席上限 + 每日愿灯）+ 静态托管（含 jpg/webp MIME）
- `assets/art/` — 两张 AI 原画 + 8 张程序化贴图（运行时加载）
- `assets/models/*.glb` — Blender 建模资产（monk / cushion / toad），`tools/gen_blender_models.py` 生成，可重跑
- `tools/blender/` — Blender 4.2 LTS 便携版（免安装，`gen_blender_models.py` 依赖它运行）
- `tools/gen_art.py` — 原画去水印 / 压缩 + 程序化贴图生成脚本
- `sfx/*.wav` — 离线生成的木鱼 / 念珠 / 点灯采样；`tools/gen_sfx.py` 是生成脚本，可重跑替换
- `start.bat` — Windows 一键启动
- `vendor/three.module.js` + `vendor/three.core.js` — 本地化 Three.js r187，**缺一不可**
- `assets/bg.png` — 早先生成的 2D 手绘背景图，暂未使用
- `package.json` / `node_modules` — 运行依赖（ws、three）
