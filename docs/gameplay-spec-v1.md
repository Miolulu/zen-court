## 0. 一句话定位

**可逛的禅意空间**：没有主玩法、没有目标、没有进度、没有计数。空间、光影、材质与镜头是主体，交互是「氛围触点」而非任务。判断一个改动该不该做，只问一句：它让这个空间更好看 / 更好待吗？

## 3. 规则闭合（氛围触点的输入 / 输出 / 边界）

| 触点 | 输入 | 输出 | 边界 |
|---|---|---|---|
| 擦拭佛像 | 点佛像 → 聚焦 → 指针/手指拖拽 | 水痕与布面逐渐洁净、局部光泽变化、完成一声轻磬 | 无进度数字、无计数、无奖励；洁净态本次会话内保持，刷新复原 |
| 求签解签 | 点签筒 → 摇动（手势或点击） | 从 32 签中出一签，卷轴展示签题 / 四句偈 / 白话解 | 无限次、不记次数、不存历史；每日一偈按本地日期确定性取一签 |
| 撸猫 | 点猫 → 聚焦 → 抚摸 / 逗弄 2–3 组手势 | 猫的几组即时反应与呼噜声 | 无好感度、无成长、无解锁 |
| 放飞愿灯 | 点灯 → 写一句 → 松手 | 灯升空、缓慢飘远、夜色里渐隐 | 不落库、不留存、不限制次数；服务端 lamp 每日校验移除 |
| 观赏树 | 点树 / 靠近 | 叶色与光影随晨昏、天气缓慢变化；可系一条飘带（本次会话可见） | 无成长计时、无阶段、无全院共养、无浇水数值 |

**轻量彩蛋**：碑刻 UI 展示预设偈语、可写一句本次会话可见的字；斋饭为点击后一碗热气的短动画；落叶随风聚散（纯环境粒子，不可扫、不计次）；挂单僧固定立于廊下，点击轮转 5 句对话。

**统一规则**：所有触点走同一套轻量交互生命周期（靠近 → 聚焦 → 手势 → 完成 → 收起），只允许视觉与音效反馈，不写任何计数型存档。失败态（离线 / 加载中）只给安静的文字提示，不弹错误横幅打断氛围。

## 4. 四条视觉线的精做清单

### 4.1 场景渲染（批 1 · 最高优先级，氛围观赏的本体）
- 构图重做：前 / 中 / 后景分层，用松枝与廊柱做天然框景，中轴纵深拉长，上三分之一保留水墨留白。
- 光影路径：晨光斜射 + 佛前唯一暖光；长柔影、近远雾过渡；`Fog(30,100)` 与水墨背景改为渐变衔接，去掉硬切线。
- 材质升级：石板 / 木构 / 瓦当 / 布面补程序化 PBR（法线、粗糙度、AO）；`tools/gen_art.py` 的两个输入 `backdrop.png`、`buddha.png` 已缺失，脚本需改为纯程序化或从会话根 `tools/ref/` 找回原图。
- 后处理：**vendor 目前没有 `EffectComposer` / `SSAOPass` / `UnrealBloomPass` / `BokehPass`**，需补与 r187 匹配的 `examples/jsm` 模块并接 importmap；AO、色调分级、克制 Bloom、可选景深。桌面开全档，手机按 dpr 1.5 降级或关闭。
- 镜头语言：入场缓推运镜、聚焦时的推拉与视角微转、收起回位；不再用固定第三人称硬切。

### 4.2 建模（批 2）
- 用 `3d-modeling` 专家出概念三视图与质量红线自检，`blender-operation` 走 `--background` 重跑 `gen_blender_models.py`。
- 本轮只精做 **1–2 个最显眼模型**（大佛 + 小沙弥或布偶猫），其余沿用现有 GLB，不追求全量翻新。
- **返工红线**：重做模型会连带影响 `GLB_MATS` 材质名映射、`grpHands` / `bowPivot` / `kneeL/R` 动画节点名，以及 6 个 `renderPropSprite()` 同源放大面板。必须先定稿拆件表 → 单个替换 → 逐项回归，禁止一次性换掉 4 个 GLB。

### 4.3 交互视觉（批 1 轻量底座 + 批 3 精修）
- 泛化 `openFocus()` / `closeFocus()` / `focusTap()`，去掉 fish / beads / pet / lamp 硬编码分支，把 6 个现有面板收编进统一生命周期。
- 反馈语言统一：可交互物脚下极淡柔光、聚焦时的描边与镜头推拉、手势连续反馈、完成仪式的粒子与一声音效；不放进度条、不放数字。
- 手机端保留 22px 触摸容差、禁 tap-highlight、hoverTip 仅鼠标、`touch-action` 与 `visualViewport` 处理。

### 4.4 UI / 进场（批 3）
- `frontend-design` + `web-design-engineer`：进场页、卷轴签文、HUD、放大面板的排版 / 字体 / 动效与浏览器视觉验收。
- 32 签文案：签题 + 四句偈 + 白话解，清雅禅意 + 答案之书式短句，不写吉凶迷信。
- 保持 v2 色板：宣纸米 `#ECE5D5` / 墨青 `#2E3532` / 低饱和朱砂 `#96574C` + 旧金 `#B49A68`，单图用色 ≤4、金色占比 ≤5%。

## 7. 验收标准

- `node --check game.js` / `server.js` 通过；无控制台报错、无错误横幅。
- Edge CDP 三视口回归：390×844 竖屏 / 844×390 横屏 / 1440×900 桌面，UI 碰撞与溢出为 0、tap 高亮透明、无悬浮或穿模。
- 双人 ws 冒烟：`welcome` / `peerJoin` / `peerMove` / `peerAction` 全链路通；愿灯可反复放飞。
- 桌面与手机后处理分档生效，手机帧率不因后处理明显下降。
- 每个 GLB 替换后单独验证：合十 / 跪拜动画、`GLB_MATS` 覆盖、6 个同源放大面板无破图。
- 每批：推送 GitHub → 重新部署多人版 → 同步 Pages 镜像与作品集详情页 → 截图确认。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 无主玩法，做完仍可能「觉得空」 | 用构图层次、光影节奏、镜头语言、环境音与微交互补；每批截图先过你的眼再继续 |
| 重做模型破坏动画节点与同源面板 | 只做 1–2 个、先定拆件表、单个替换逐项回归 |
| vendor 缺后处理模块 | 补 r187 匹配模块并接 importmap；手机降级或关闭 |
| `gen_art.py` 输入缺失 | 改纯程序化或从会话根 `tools/ref/` 找回原图 |
| 关键脚本不在版本库 | 会话根 `tools/` 未纳入 git、`zen-court/tools/` 被 `.gitignore` 忽略；本轮把建模与回归脚本纳入版本管理或显式备份 |
| 图像生成积分 | 上限 2 张（约 10–20 积分），每张先给你看再决定下一张 |
| 单文件膨胀 | `game.js` 3137 行起，本轮按批次拆 ES 模块；`defaultSave()` 新增字段须同步改默认值 |
| 云服务 | **不启用**，无计费、无合规风险；若日后反悔要加共享 UGC，需重开数据层设计 |

## 9. 概念稿 v2 评估

`docs/concept/hero-v2.png`（1536×932，已裁去平台水印，带水印原稿归档在 `concept/old/`）：符合风格锚点，具备前中后景、左右框景、上三分之一留白、右上方斜阳、佛前唯一暖光；空间成为主体，人物仅作比例尺；无文字、无汉字、无水印。

**使用边界**：画面里的「悬浮岛与大面积水面倒影」是生成模型的自由发挥，**只作光影、构图、色板锚点，不照搬到 3D 场景**——实际场景仍是平地庭院。银杏黄略高于 v2 色板，落地时按旧金 `#B49A68` 收敛。

v1 与 v2 并列留档、不覆盖：v1 锁风格，v2 锁「空间即主体」的构图与光影。
